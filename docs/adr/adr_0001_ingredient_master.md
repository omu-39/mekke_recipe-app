# 0001. 食材マスタ方式を採用

## ステータス

確定

## コンテキスト

レシピアプリの中核機能は「所持食材から、不足材料数に応じて作れるレシピを分類表示する」ことである
（`use_cases.md` UC-04）。この判定ロジックが正しく機能するには、所持食材とレシピ材料の食材名が
文字列として厳密に一致する必要がある。

食材名を自由入力にした場合、以下のような表記ゆれが発生し、判定精度が損なわれる懸念があった。

- 「じゃがいも」「ジャガイモ」「馬鈴薯」のような表記の揺れ
- 「玉ねぎ」「玉葱」「たまねぎ」のような漢字・かな・カタカナの揺れ
- 単位や修飾語の混入（「新玉ねぎ」「玉ねぎ（中）」等）

これらを名寄せ・正規化する仕組みをMVPの段階で作り込むのは開発コストが高く、
判定ロジックの信頼性を優先する必要があった。

## 決定

MVPでは、食材の登録（所持食材登録・UC-03-02）・レシピ材料の入力（レシピ投稿・UC-06-01）
の両方について、**自由入力を許可せず、事前に用意した食材マスタからの選択のみ**とする。

- 所持食材の登録は食材マスタから選択する（`recipe_app_spec_v2.md` 7.7節）
- レシピ投稿時の材料入力も同じ食材マスタから選択する（7.6節）
- 不足材料の判定は、食材マスタのIDベースの一致判定で行う（10章）

## 影響

- 表記ゆれによる誤判定を原則発生させずに済む（`recipe_app_spec_v2.md` 10章参照）
- 一方で、食材マスタに存在しない食材は登録・使用ができない。マスタの初期データ整備方法
  （外部APIからの抽出 or 手動作成）は別途検討が必要（12.1節）
- 将来的に自由入力＋表記ゆれ吸収（正規化）への対応、食材マスタへの追加リクエスト機能の
  導入を検討する余地を残す（3.6節・12.1節参照）
